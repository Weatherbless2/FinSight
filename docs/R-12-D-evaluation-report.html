3. 结果解读

  • 向量检索：本次 Recall@5 为 100%，对中文问题和英文财报之间的语义匹配最稳定；P95 为 56.580 ms。
  • Hybrid：Recall@5 为 97.22%，MRR 为 0.8704；同时使用全文词项和向量相似度，P95 为 55.803 ms。
  • 关键词：Recall@5 为 80.56%，P95 仅 6.990 ms，适合股票代码、明确财报术语等精确查询。
  • Agentic：复用了有限轮数、查询次数和上下文预算；本次结果低于向量基线，说明“增加 Agent”不会自动带来效果提升，仍需要针对查询改写和停止条件优化。

5. 关键实现

# 先做金融安全过滤，再做向量排序
WHERE d.ticker = :ticker
  AND d.available_at <= :as_of
  AND c.embedding IS NOT NULL
ORDER BY c.embedding <=> CAST(:query_vector AS vector)
LIMIT :limit

# Hybrid 用两路排名做 Reciprocal Rank Fusion
score = sum(1 / (rrf_k + rank) for rank in keyword_rank, vector_rank)

这段设计的业务含义是：模型或检索策略不能绕过日期边界。即使未来文档与问题语义非常相似，也会在数据库候选阶段被排除。

6. 面试说法

30 秒版本：我先把真实 SEC 财报和公告清洗切成 1,092 个 Chunk，写入 PostgreSQL，并用 Ollama 生成 1,092 条 1,536 维向量。随后固定 30 道投研问题，使用相同的股票和交易日期，比较关键词、向量、Hybrid 和受约束 Agentic 四种检索。实测向量 Recall@5 为 100%，Hybrid 为 97.22%，关键词为 80.56%，四种策略未来泄露率都是 0；同时记录 P95 延迟，避免只凭主观感觉说 RAG 有提升。

为什么没有直接选 Agentic？ Agentic 增加了查询改写和策略决策能力，但也增加了路径不确定性和耗时。本次评测中 Agentic Recall@5 为 83.33%，低于向量基线，所以后续应先分析 Bad Case，再调整查询改写、停止条件和融合排序，而不是盲目增加 Agent 轮数。
