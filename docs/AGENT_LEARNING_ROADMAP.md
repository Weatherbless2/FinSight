## 已确认的架构结论

- 分析师内部采用类似“思考—行动—观察”的循环：模型决定是否调用工具，工具结果再回到同一智能体。
- 整体采用固定顺序、有限循环的 LangGraph 工作流，不是完全自由的自主智能体。
- 智能体通过中心化 `AgentState` 交接报告和辩论状态。
- `messages` 是短期上下文；Markdown 决策日志是长期经验；SQLite 检查点是故障恢复，三者不是同一件事。
- 数据日期过滤、供应商降级、无数据标记是金融场景的确定性安全边界。

## 范围约束

- 不把检索增强生成描述为当前已有能力，它应是可插拔的数据源扩展。
- 不接真实券商，除非先完成权限、审批、幂等、风控和审计。
- 不为了展示“自主”删除固定工作流；金融任务优先可控、可回放、可解释。
- 不只增加智能体数量；每个角色必须有独立输入、输出、工具和可评测收益。

## 完成后的项目定位

> TradingAgents 使用 LangChain 封装模型和工具，使用 LangGraph 构建有状态的固定工作流。分析师节点内部采用工具调用循环，随后经过多智能体辩论、结构化计划、交易提案和风险复核生成最终评级。通过继续补强工具可靠性、上下文和记忆、调用链与成本、智能体评测以及 FastAPI 服务化，项目既能解释智能体原理，也能体现互联网工程落地能力。
