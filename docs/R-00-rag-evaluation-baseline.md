# R-00：建立 RAG 评测基线

## 问题

在接入 PostgreSQL、向量检索或 Agentic RAG 之前，如何定义“检索正确”“引用可信”和“没有偷看未来数据”，并让后续优化可以重复比较？

## 已核验基线

当前 TradeAgent 已有金融数据 API、多智能体工作流和确定性日期保护，但没有文档知识库、RAG 检索器或 RAG 评测集。因此本工单只建立评测规格和固定样本，不声称已经完成 RAG。

## 本次完成内容

- 增加 `tests/fixtures/rag_eval_cases.json`，定义 12 个文档元数据样本和 30 条评测问题。
- 覆盖事实查询、跨期对比、原因分析、未来信息拦截、证据不足五类问题。
- 为每条问题记录股票、分析日期、标准证据文档、标准章节和回答模式。
- 增加 `tests/test_rag_eval_cases.py`，只做评测清单加载、数量结构和日期边界的轻量冒烟校验。
- 明确后续统一指标：Recall@5、MRR、Citation Coverage、Unsupported Claim Rate、Future Leakage Rate、P95 延迟和 Token 消耗。

## 运行方式

```bash
pytest -q tests/test_rag_eval_cases.py
```

## 验收标准

- 评测问题数量固定为 30 条，每类 6 条。
- 评测问题 ID 唯一，股票代码只使用 AAPL、MSFT、NVDA。
- 每条问题都有 `trade_date` 和 `answer_mode`。
- 正常问题的标准证据文档必须存在于文档目录，且 `available_at <= trade_date`。
- 未来信息拦截题必须明确列出禁止使用的未来文档。
- 证据不足题不允许填写标准证据文档，回答模式必须为拒答或证据不足。

## 实测结果

本工单只记录清单冒烟校验的通过数量、失败数量和耗时。Recall@5、MRR、引用覆盖率、P95 和 Token 对比统一延后到 R-12；在 R-08 之前没有检索器，不能声称已有这些结果。

## 设计取舍

样本先使用稳定的文档 ID 和章节名，不在本工单下载外部文档，也不依赖真实模型或网络。这样评测规则可以先进入持续集成，后续 R-04 导入真实 SEC/公司 IR 文档时只需要把文档 ID 映射到实际来源。

## 30 秒面试答案

我没有先接向量库再凭感觉判断效果，而是先建立固定的 30 条金融研究问题和标准证据。问题覆盖事实、跨期比较、原因分析、证据不足和未来信息拦截；每条都绑定股票与分析日期。后续会用 Recall@5、引用覆盖率和未来信息泄露率比较关键词、向量、Hybrid 和 Agentic RAG，其中未来信息泄露率必须为零。

## 当前限制与下一步

当前只是评测基线，不包含真实文档文本、解析、切分、Embedding 或检索结果。下一张工单是 R-01/R-02：先固化文档元数据契约，再部署 PostgreSQL + pgvector。
